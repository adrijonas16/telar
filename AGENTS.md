# Telar: guide for coding agents and contributors

Telar is a browser-only visual studio for the **open agentic web**: people design agent
networks on a canvas, Telar checks them against the
[Open Agentic Web MVP specification](https://github.com/cognizant-ai-labs/agentic-web/blob/main/docs/worldwide_agentic_web_mvp_spec.md),
and exports the files a website publishes. Telar is itself an open agentic website: its
assistant **Ask Telar** edits the canvas through site actions.

Live: https://adrijonas16.github.io/telar/ · Built for the Open Agentic Web Challenge (deadline
2027-01-11 08:00 PT).

## Commands

```sh
npm run dev           # Vite dev server
npm run check         # typecheck + lint + tests: keep it green before every commit
npm run build         # static site in dist/ (GitHub Pages deploys main automatically)
npm run build:agent   # rebuild Ask Telar's network from agent/telar_assistant.hocon
npm run check:agent   # CI: fails if public/ is out of date or the network has warnings
npx prettier --write .
```

## Architecture rules (enforced by lint or tests where possible)

1. **`src/core/` is pure TypeScript**: no DOM, no `window`/`localStorage`, no Lit, no imports from
   `ui/` or `persistence/` (ESLint enforces it). It must run in Node tests.
2. **Every edit is a pure command** `(doc, ...) => doc` in `core/model/commands.ts`. Components
   never mutate state; they call intent-level methods on `StudioController` (`src/ui/controller.ts`).
3. **Derive, don't store.** `network.json`, `agent-manifest.json`, `links.json` and the validation
   report are computed from the document.
4. **Lossless import/export.** Unknown fields go to `extra`/`functionExtra`/`metadataExtra`. The
   official examples must round-trip unchanged (`tests/core/serialize.test.ts`).
5. **Never edit vendored code**: `src/core/validate/vendor/` (reference validator),
   `public/runtime/` and `.claude/skills/agentify-website/` (official runtime and skill). Refresh
   them by copying newer upstream versions, then run the tests.
6. **Light DOM for the runtime.** The assistant mounts in `#assistant` in `index.html` because the
   runtime uses `document.querySelector`; everything else is Lit with Shadow DOM.
7. **UI text in English** (the challenge submission is in English). Sentence case, plain words:
   "Entry point", not "front_man".

## Ask Telar (the agent) in one minute

- **Prompt source:** `agent/telar_assistant.hocon`. Only Telar's own lines are ours; the
  `grounding_rules` scaffolding, `peer_rules` and `cruse_rules` come from the official template.
  Instruction budget: 5000 characters (the build warns).
- **Tools:** `public/site-actions.js` (13 actions) → `TelarPage` (`src/ui/page-api.ts`) →
  `StudioController`. All writes are one undo step, so no action is `irreversible`.
- **Published files:** `public/agent-manifest.json` (edit by hand), the rest of `public/*.json`,
  `public/.well-known/` and `public/bridge/` are generated by `npm run build:agent`.

## Lessons already learned (do not rediscover them)

- The runtime keeps no tool results from earlier turns; agents must re-read state each turn.
- "Save and start" in the runtime's AI settings reloads the page.
- Shadow DOM does not inherit `box-sizing`; shared styles reset it (`ui/styles/shared.ts`).
- Long JSON in a grid cell needs `minmax(0, 1fr)` tracks or it pushes panels off screen.
- Fonts inlined as `data:` URIs need `font-src 'self' data:` in the CSP.
- Networks published from Telar need the template's peer rule, or `check_partner.mjs` warns;
  Telar flags it (`agentic.peer-rule`) and `build_network` adds it.
- The official guidance prefers **one front agent with all site tools**; split agents only for
  separate knowledge, a separate system (MCP) or a separate workflow, not per department.
